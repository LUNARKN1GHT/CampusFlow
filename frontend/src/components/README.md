# 共享组件

本目录放跨页面复用、不承担业务编排的 Vue 单文件组件。页面放 `../views/`，HTTP 调用集中在 `../api/`，会话与主题等跨页面状态放 `../composables/`，路由表与登录守卫在 `../router.ts`。

## 现有组件

| 组件 | 职责 | 使用位置 |
| --- | --- | --- |
| `AppShell.vue` | 受保护页面主布局：顶部单行导航（只列已开放入口）、深浅模式切换、账号与退出，并承载子路由出口 | 除登录页外的全部页面（`router.ts` 父路由） |
| `ApiFeedback.vue` | 统一失败提示：`role="alert"` 播报、重试按钮与加载中状态，`busy` 由调用方传入 | 课程、资料库、任务、学习计划、提醒、导出、设置、总览与固定日程组件 |
| `FixedSchedule.vue` | 固定日程周视图：读取日程定义与按周实例，编辑只作用于定义；时刻按工作空间时区解释 | 任务页 |
| `MaterialLifecycle.vue` | 资料归档与删除面板：归档只切换标记，删除先预览影响并携带确认令牌，内容变化后令牌失效需重新预览 | 资料库页面 |
| `MaterialSource.vue` | 原文定位面板：按引用所属版本打开片段并尽量高亮同一段文字、页码或截图区域；原文不可读时标注“无法验证” | 资料库页面 |

## 新增组件约定

- 只在两个及以上页面复用、或职责边界明确时才放进本目录；单页专用结构留在对应页面，不为了“看起来整齐”提前拆分。
- 组件通过 props／emit 与页面交互，业务规则留在后端；组件不自行判断事实、生效版本或冲突，只展示接口返回值与限制说明。
- HTTP 调用经 `api/` 层，失败统一交给 `ApiFeedback` 呈现；不把演示数据当成真实任务或资料。
- 样式只使用 `styles.css` 的语义 token（`:root`、`:root[data-theme="dark"]`、`:root[data-palette=…]`），不写死色值，保证深浅模式与色系切换生效。
- 删除、归档、外部写入等敏感操作必须先展示范围与影响，再携带预览签发的确认令牌执行；组件不能复用旧确认执行新内容。
- 空状态、部分失败与未覆盖范围要写明原因，不用“没有数据”掩盖识别失败或权限不足。
- 新增或调整组件时同步更新本表，写清职责与使用位置。
