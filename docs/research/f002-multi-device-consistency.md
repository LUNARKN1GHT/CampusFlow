# F002 评估：多设备访问与数据一致性需求

- Issue：#219（F002）· 父 Issue #27（EF0）
- 范围：后续探索，未承诺开发阶段或日期
- 日期：2026-09-30

## 目标场景

| 场景 | 描述 | 典型需求 |
| --- | --- | --- |
| 多端访问 | 手机看计划、电脑导入资料 | 同一账号在不同设备看到同一份数据 |
| 弱网/离线 | 图书馆或地铁上网络不稳 | 本地可查看已加载内容，联网后同步 |
| 会话安全 | 多设备同时登录 | 会话隔离、异常登录提示、可登出全部设备 |
| 冲突处理 | 两个设备同时改了同一任务 | 明确"最后写入"或逐字段合并规则，不静默覆盖 |

## 成本估计（若立项）

| 项目 | 成本级别 | 说明 |
| --- | --- | --- |
| 账号体系与工作空间授权 | 高 | 当前单用户无认证；多设备的前提是账号与授权（依赖 W006 及后续认证工作） |
| 服务端状态同步 | 中 | 后端已是事实来源，主要工作是离线缓存与增量拉取 |
| 离线与冲突策略 | 中 | 需要定义同步协议与冲突界面，测试面明显扩大 |
| 多端适配 | 高 | 前端目前仅桌面浏览器布局，移动端需另行设计 |

## 结论与前置条件

- **暂不立项**：前三阶段聚焦单设备桌面浏览器，多设备不纳入交付范围 ✅
- 前置条件：完成账号体系与工作空间访问控制；后端 API 保持无状态、可水平访问后，再做客户端缓存与同步 ✅
- 立项目标（如未来启动）：手机端只读查看计划与截止提醒优先，编辑类功能后置 ✅
