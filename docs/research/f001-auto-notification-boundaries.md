# F001 评估：自动通知更新的来源与授权边界

- Issue：#185（F001）· 父 Issue #27（EF0）
- 范围：后续探索，未承诺开发阶段或日期；本结论未经范围决策不得纳入前三阶段交付
- 日期：2026-09-30

## 调研范围

比较三种让系统获得"新通知"的方式：公开通知订阅、用户主动触发、后台自动更新。

## 三种方式对比

| 方式 | 做法 | 可行性与风险 |
| --- | --- | --- |
| 公开通知订阅 | 订阅目标页面的公开更新（RSS、公众号推送、公开网页监测） | 仅适用于公开可访问页面；教务类页面多数需要登录，可订阅范围有限；公开可读不等于允许再分发 |
| 用户主动触发 | 用户把新通知上传/粘贴进系统，或手动触发重新导入 | 零额外权限、零后台运行，是当前首期方案（README §4.9）；缺点是依赖用户记得操作 |
| 后台自动更新 | 系统定时登录/抓取目标页面并比对变化 | 需要凭证存储与授权、频率控制、稳定性保障；自动登录属于高风险操作，与产品"不自动登录教务系统"的边界冲突（README §8） |

## 访问权限建议

1. 只自动处理**公开可访问**的页面，且遵守目标站点的服务条款与 robots 约定。
2. 需要登录的页面**不自动抓取**：改为用户主动导入或粘贴原文，登录凭证永不进入系统。
3. 公开页面抓取仅用于用户自己工作空间的资料更新，不对外转发、不公开转载。
4. 抓取行为对目标站点保持低频、失败退避，不得造成访问压力。

## 更新频率建议

1. 前三阶段**不启用后台自动更新**；变更入口保持"用户主动导入新资料"。
2. 若后续立项：频率上限按天计（如每日一次、非整点错峰）；仅在检测到内容变化时生成变更草案，不因"又抓了一次"制造重复事项。
3. 自动抓取失败不得影响已有安排：失败静默记录并可重试，不展示为"已更新"。

## 与 Issue #2（QQbot）的关系

#2 提议接入 QQ 机器人自动过滤群聊信息。该方案需要机器人账号权限、群消息读取授权与消息转发存储的同意机制，属于比自动网页更新更敏感的探索方向：

- 建议与 F001 一并留在后续探索范围，不纳入前三阶段；
- 若未来评估，先解决"群成员知情与同意"与"消息内容归属"，再讨论技术方案。

## 结论

- 前三阶段维持"用户主动导入"为唯一变更入口 ✅
- 公开页面订阅与后台更新列为后续探索，立项前置条件：目标站点公开性核实、授权边界确认、频率与失败策略 ✅
- 不自动登录、不绕过登录、不自动执行写入类操作 ✅
