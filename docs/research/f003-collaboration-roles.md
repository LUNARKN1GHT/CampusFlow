# F003 评估：协作共享和角色权限范围

- Issue：#220（F003）· 父 Issue #27（EF0）
- 范围：后续探索，未承诺开发阶段或日期

## 问题界定

README §1 已明确：教师协作、班级管理和学校级教务管理属于独立评估范围，首期聚焦学生个人工作空间。本文回答"协作共享"需要哪些角色与权限，以及为什么不能默认开放。

## 角色与权限需求（若立项）

| 角色 | 需要的能力 | 敏感点 |
| --- | --- | --- |
| 学生本人 | 管理自己的工作空间 | 本人数据本人可导出、可删除 |
| 同学（共享对象） | 只读查看共享的任务/日程 | 不得获得资料原文的转发权限 |
| 教师/助教（若评估教师协作） | 发布公告、查看教学班任务统计 | 只能看到学生主动共享的完成状态，不能查看私人资料 |
| 班级管理员（若评估班级管理） | 维护班级成员与教学班信息 | 成员加入需本人确认，退群可撤销共享 |

## 共享授权与撤销需求

1. 共享的最小单元是**具体对象**（一份任务/一个日程），不是整个工作空间。
2. 共享前展示将暴露的内容范围；接受方不能把共享内容再转发。
3. 任何共享都可随时撤销；撤销后对方不再可见，且系统提示"内容已不再共享"。
4. 个人资料原文（上传的 PDF、截图）**默认不参与任何共享**；确有需要时单独授权。

## 结论

- 教师协作、班级管理**不属于前三阶段产品范围**，作为独立产品方向评估 ✅
- 个人工作空间数据**默认不开放**，共享必须逐对象授权且可撤销 ✅
- 若未来立项，优先做"任务/日程只读共享"，原文共享与教师端功能后置 ✅
