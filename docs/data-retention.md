# 资料备份保留与删除策略（D010）

- Issue：#93（D010）· 父 Issue #8（E20）
- 适用范围：本地私有存储（当前）与未来引入的备份机制
- 依据：README §7 删除与备份保留；AGENTS.md 数据边界

## 保留期限

| 对象 | 保留策略 |
| --- | --- |
| 私有存储原文件（`data/materials`） | 删除资料时**立即删除**原文件；不做延迟保留 |
| 数据库记录（资料/版本/片段） | 删除时随资料级联删除，不保留墓碑记录 |
| Docker 命名卷 | 仅在 `docker compose down -v` 时清除；常规停止不影响 |
| 未来引入的备份 | 建议滚动保留 **30 天**（可通过配置调整），到期备份自动清除；备份中的已删除资料随备份到期一并消失 |

## 删除界面说明

删除影响预览（`GET /api/v1/materials/{id}/delete-impact`）响应包含 `backup_note` 字段，
向用户说明：本地存储立即删除；若启用备份，残留副本将在配置的保留期限（默认 30 天）
到期后随备份轮换清除。期限来自 `CAMPUSFLOW_BACKUP_RETENTION_DAYS` 配置。

## 恢复对账流程（防止恢复后悄悄复活已删除资料）

1. **记录删除**：每次确认删除写入删除操作记录（时间、资料 ID、确认指纹）。
2. **从备份恢复时**：恢复完成后，读取备份中不存在的删除记录所对应时间点之后的所有删除记录。
3. **对账执行**：对恢复数据中仍存在、但恢复时间点之后已被删除的资料，重新执行删除；对账结果写入日志，未对账完成前不把恢复环境视为可用。
4. **禁止静默复活**：任何恢复流程不得在没有对账的情况下直接上线；对账失败按故障处理。

当前本地开发环境无自动备份，恢复对账在引入备份机制时落地；删除操作记录届时随备份功能一并实现。
