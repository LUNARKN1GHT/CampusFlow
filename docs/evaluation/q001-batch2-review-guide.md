# Q001 第二批样本人工复核说明书

任务：[Q001 #128](https://github.com/LUNARKN1GHT/CampusFlow/issues/128) 的独立人工复核（第二批）。整理：金嘉睿（24151735）。2026-10-16。

## 一、这次复核什么

Q001 要回答的问题是：**中文检索问答该选哪一组模型**（两个向量模型 × 两个回答模型，共四组）。

前面三轮用的是同一批 9 道题，而题目在调提示词的过程中被反复看过，**不能算「没见过的新题」**。所以又做了一批：

- 在已有的课程范围里塞进措辞很像、但不是答案的干扰资料，看检索挑不挑得中；另外两段刻意属于别的学期、别的工作空间，看范围会不会串；
- 加 6 道全新的题目，这 6 道**从没参与过调提示词**。

这批跑完发现：**四组配置的检索成绩完全一样（都 100% 挑中），差别出在回答上**。所以这一轮复核的价值，就是判清楚「模型的回答到底对不对」。

脚本能自动做的只有**字面比对**——把模型答的话和人工写的标准答案一个字一个字对。措辞稍有不同脚本就判不了，只能标成「待人工核对」。所以必须你来判**模型说的意思对不对**，以及**作者写的标准答案本身对不对**。

你**不需要读代码，也不需要跑任何命令**，只要打开两份表格，照着下面的规则填数字。

## 三、逐条回答复核（121 行那份）

### 3.1 先看这几栏，它们是给你判断用的

| 列名 | 说的是什么 |
| --- | --- |
| `问题` | 用户问了什么 |
| `原资料（编号｜原文）` | 系统这次检索到、交给模型的原文片段，方括号里是编号 |
| `模型主张（含引用编号）` | 模型给出的结论，每条下面写着它引用了哪个编号 |
| `模型不确定提示` | 模型自己主动提示「这里说不准」的地方 |
| `人工预标注要点` | 作者事先写的标准答案，以及它对应的原文原话 |

另外两栏是**脚本已经自动查出来的**，你不用自己再查：

| 列名 | 含义 |
| --- | --- |
| `系统检出-坏引用编号` | 模型引用的编号不存在。**这一批 121 行全部为空**，也就是没有错引。 |
| `系统检出-检索命中/应有` | 检索捞到了几条 / 本应捞到几条。**凡是有资料可检索的行，四组配置全部命中**（显示 `1/1` 或 `2/2`）。显示 `0/0` 的 16 行是刻意准备的「这门课没有任何资料」题目（美术课、音乐课），本来就该捞不到东西，属正常，不用在 `notes` 里写异常。真出现 `0/1` 才要写一句「检索没捞到，模型答不上来是被检索拖累的」。 |

### 3.2 再填这八栏

| 列名 | 怎么填 | 填什么 |
| --- | --- | --- |
| `total_claims` | 数 `模型主张` 那栏里有几个编号 | 整数 |
| `supported_claims` | 这几条里，有几条**能被原资料直接证明** | 整数，不能大于 `total_claims` |
| `output_uncertainties` | 数 `模型不确定提示` 那栏里有几个编号 | 整数 |
| `correct_uncertainties` | 这几条里，有几条**确实该提醒** | 整数，不能大于 `output_uncertainties` |
| `hard_failures` | 有没有踩红线（见第五节） | 没踩填 `否`；踩了填代码 |
| `reviewer` | 你的名字或 GitHub 用户名 | 文字 |
| `reviewed_at` | 你复核的日期 | `2026-10-17` 这样的格式 |
| `notes` | 拿不准、有争议、想说明的 | 文字，可以留空 |

判断「能不能被原文证明」时注意两点：

1. **编号对不等于内容对**。模型引用 `physics-a-2nd`，但说成「10 月 10 日交」而原文写的是 10 月 24 日——编号是对的，内容错了，这条**不算支持**。
2. **意思对就算对，不要抠字眼**。这正是脚本判不了、需要你来的地方。模型用自己的话复述原文、意思一致，就算支持。

## 四、四个真实例子（都取自本批表格）

### 例子一：序号 14，完全正确

- 问题：大学物理A班第二次习题什么时候交？
- 模型主张：`1. 大学物理A班第二次习题须在2026年10月24日20:00前通过课程平台提交。引用编号：physics-a-2nd`
- 原资料里同时给到了「第一次习题 10月10日」和「第二次习题 10月24日」两条，模型挑对了。
- 模型不确定提示：空

填法：`total_claims = 1`，`supported_claims = 1`，`output_uncertainties = 0`，`correct_uncertainties = 0`，`hard_failures = 否`。

### 例子二：序号 13，两份通知打架，模型如实指出

- 问题：数据结构期末考试是什么时候？
- 模型主张：`1. ……定于2026年12月28日上午9:00至11:00。引用编号：ds-exam-v1`、`2. ……调整至2026年12月29日下午14:00至16:00。引用编号：ds-exam-v2`
- 模型不确定提示：`1. conflict 说明：两个来源提供了不同的考试时间，存在矛盾。`
- 人工预标注不确定项：`1. source_conflict`

模型没有擅自挑一个日期，而是把两份都摆出来并说明冲突——**这是正确做法**。

填法：`total_claims = 2`，`supported_claims = 2`，`output_uncertainties = 1`，`correct_uncertainties = 1`，`hard_failures = 否`。

### 例子三：序号 15，模型说「没找到资料」，其实资料就在眼前

- 问题：操作系统实验二的截止时间是什么？
- 原资料：`[os-lab2] 操作系统实验二为进程调度模拟，题目见附件，提交方式另行通知。`
- 模型结论：`insufficient`（意为「没有相关资料」）
- 模型不确定提示：`1. 缺失截止时间信息 说明：现有资料中未发现操作系统实验二的截止时间信息。`
- 人工预标注不确定项：`1. missing_deadline`

这里要分清两件事：

1. **不确定提示本身是对的**——「缺截止时间」确实是该提醒的事，所以 `output_uncertainties = 1`、`correct_uncertainties = 1`。
2. **模型的结论标签用词不准**——它标成 `insufficient`（没有相关资料），可表里明明检索到了「操作系统实验二」这条通知，只是没写截止时间。按项目规则（资料相关但关键信息缺失 = `uncertain`，完全找不到相关资料才 = `insufficient`），这里应该是 `uncertain`。

填法：`total_claims = 0`，`supported_claims = 0`，`output_uncertainties = 1`，`correct_uncertainties = 1`，`hard_failures = 否`，`notes` 写「结论标签写成 insufficient，应为 uncertain；不确定提示内容正确」。

这一批里好几个回答都是这个毛病（序号 3、12、15 等），请都按这个办法处理。

### 例子四：序号 3，加了干扰资料后模型被带偏

- 问题：物理A班的练习应该交到哪儿？
- 原资料：同时给到了「第一次习题：通过课程平台提交」「第二次习题：通过课程平台提交」「期中考试安排」三条。
- 模型结论：`insufficient`，主张为空，提示「现有资料中未提及物理A班练习的提交地点」。
- 人工预标注要点：`1. 通过课程平台提交。`

原文两处都写了「通过课程平台提交」，模型却说没提。**这条不是格式问题，是答错了**：`total_claims = 0`，`supported_claims = 0`，`output_uncertainties = 1`（它提了「缺失信息」），`correct_uncertainties = 0`（原文明明写了，不该提醒），`hard_failures = 否`，`notes` 写「原文已写明通过课程平台提交，模型误判为资料缺失」。

## 五、红线（`hard_failures`）

这是比「答错」更严重的问题：答错是能力问题，踩红线是**把不确定的东西说成确定的**。踩了就填代码，多条用分号隔开（例如 `scope_mix;fabricated_date`）。

| 代码 | 大白话 |
| --- | --- |
| `forged_citation` | 伪造引用：引用了本次根本没给它的资料编号，或者编了一句原文里没有的「原文」 |
| `scope_mix` | 混用范围：拿别的学期、别的教学班的资料当成这门课的依据。本批数据里故意放了「物理A班的第一次习题」当「第二次习题」的干扰项，**挑错日期属于答错，不算红线**；只有把它说成「A班和B班通用」这类混淆范围才算 |
| `fabricated_date` | 把缺失的日期补成确定事实：原文只说「10月15日」没说哪一年，回答却写成「2026年10月15日」并当成已确认 |
| `dead_reference` | 资料已经删除或失效，回答还说「原文在这里可以查」 |

**老实承认不知道永远不算红线。** 模型说「资料里没写」且确实没写，即使结论标签用错了（见例子三），也填 `否`。

## 六、一种特殊行怎么填

**`回答状态` = `interrupted`**（只有序号 37 一行）：这是上次跑到一半电脑上进程被关掉留下的残行，**模型根本没产生回答**，表里对应的栏全是空的。这行已经在同一天重跑成功（另有一条完整的记录），所以：

- 四个数字都填 `0`，`hard_failures` 填 `否`，`notes` 写「进程中断，未产生回答，已重跑」

这样做是为了让「失败」看得见，同时不拿它拉高或拉低分数（B017 要求：失败按未命中计入，不能把样本剔除）。

## 七、人工标注复核（15 行那份）

这份表复核的是**作者事先写好的标准答案**：问题、应当检索到哪条资料、标准答案的内容、依据的原文、以及预期结论，都在表里。15 行对应第二批的 15 道题。

请你判断这些标注**是否合理**，然后填：

| `annotation_review` 填什么 | 什么时候填 |
| --- | --- |
| `confirmed` | 认可这条标注：问题清楚、资料选得对、标准答案有原文依据 |
| `changes_requested` | 有异议：在 `notes` 里说明哪一项不对、应该改成什么 |

**请不要直接改动表里其他栏的内容**（特别是标准答案和预标注不确定项）。有异议写在 `notes` 里，由作者去改样本文件并重跑，这样责任清楚、证据也不会被悄悄改掉。

同样要填 `reviewer` 和 `reviewed_at`。

## 九、这两份表是怎么来的

两份工作表不是手工整理的，由脚本从证据文件生成，内容逐行对应，可以重新生成核对：

```powershell
uv run --locked --project backend python scripts/prepare_q001_review_sheet.py --experiment "v4-第二批=docs/evaluation/q001-live-batch2/answer-review.csv=四组各答 15 题，含同范围与跨范围干扰资料、6 道未参与调试的新题" --annotation-source docs/evaluation/q001-live-batch2/annotation-review.csv --output docs/evaluation/q001-batch2-review-worksheet.csv --annotation-output docs/evaluation/q001-batch2-annotation-review-worksheet.csv
```

脚本**只读**证据文件，绝不改写它们；`系统检出-*` 两栏取自同目录的 `results.json`。脚本还会逐行检查两份文件是否对齐，对不上就直接报错，不会把数字填到错行上。

第二批的样本构成（哪些是干扰资料、哪 6 道是新题）见 [样本说明](../../samples/synthetic/q001/README.md)；运行过程与费用见 [进度记录](../verification/Q001-live-progress.md)。
