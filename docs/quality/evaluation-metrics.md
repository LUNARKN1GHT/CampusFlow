# 样本评估指标与记录格式

本规范用于比较解析、提取、引用问答和排期方案，不把模型输出直接视为事实。指标定义先固定，目标阈值在授权或合成样本上完成首轮基线测量后再由 Issue 决定；不得反向修改口径来美化结果。

机器可读定义见 [evaluation-metrics.json](evaluation-metrics.json)，逐次结果使用 [evaluation-record-template.csv](evaluation-record-template.csv)。运行 `python3 scripts/validate_evaluation_assets.py` 可检查每项指标的分子、分母、失败定义和待定阈值声明。

## 统一计数规则

- 评估单元使用人工预期中的字段、事实性主张、待核对项、任务或时间块；同一单元在一个指标中只计一次。
- `numerator` 和 `denominator` 均记录整数原始计数，`value` 由二者计算；不要只保存百分比。
- 分母为 0 时 `value` 留空并记 `not_applicable`，不能写成 0% 或 100%。
- 超时、解析异常、无输出和结构校验失败按各指标的失败定义计入，不因系统没有结果而排除。
- 排除项必须记录数量、原因和批准人；只允许样本损坏、标注撤回等与被测系统无关的原因。
- 每次运行固定提交、配置、解析器/模型版本和样本清单。结果至少按输入类型与场景切片，必要时再按课程、学期和教学班检查范围隔离。

## 指标定义

| ID | 指标 | 分子 | 分母 | 失败如何计入 |
| --- | --- | --- | --- | --- |
| EXT-RECALL | 事实字段召回率 | 与人工预期值及范围一致的已提取字段数 | 人工预期要求提取的字段总数 | 漏提、结构失败或运行失败均记为未命中 |
| EXT-PRECISION | 事实字段精确率 | 已提取字段中与人工预期一致且有来源的字段数 | 系统输出的事实字段总数 | 错值、错范围、无来源和重复字段均记为错误输出 |
| CIT-SUPPORT | 引用支持率 | 引用原文能够直接支持对应事实性主张的主张数 | 回答中所有需要依据的事实性主张数 | 缺引、错引、失效引用或运行失败均记为不支持 |
| UNC-RECALL | 不确定信息识别召回率 | 正确标为待核对且给出正确原因的不确定单元数 | 人工标注为不确定的单元总数 | 自动确认、遗漏原因或运行失败均记为漏检 |
| UNC-PRECISION | 不确定信息识别精确率 | 系统标记的不确定单元中人工标注确需核对的数量 | 系统标为待核对的单元总数 | 可确认事实被误报为不确定时记为误报 |
| PLAN-CONSTRAINT | 排期约束满足率 | 同时满足固定日程、DDL、依赖、锁定和时区约束的已排时间块数 | 系统生成的已排时间块总数 | 任一硬约束冲突即该块失败；生成失败按全部预期块失败记录 |
| PLAN-COVERAGE | 计划事项覆盖率 | 在已排或带原因未排列表中出现一次的输入任务数 | 进入本次计划范围的输入任务总数 | 遗漏、重复抵消遗漏或无结果均记为未覆盖 |
| EDIT-COST | 用户修改成本 | 达到可接受结果所需的字段编辑、移动、删除和新增动作总数 | 最终被用户接受的任务或计划项总数 | 未能达到可接受结果的会话另记失败，不能从分母删除 |
| REMINDER-OMISSION | 提醒遗漏率 | 应提醒但未在容差窗口内出现的事项数 | 人工预期应提醒的事项总数 | 运行失败导致未提醒时计为遗漏 |
| REMINDER-DUPLICATE | 提醒重复率 | 同一事项和触发窗口内超出一次的提醒数 | 系统实际发出的提醒总数 | 重试重复发送计入分子；分母为 0 时不适用 |
| PERF-LATENCY | 端到端处理 P95 时延 | 同场景成功运行的第 95 百分位耗时（毫秒） | 预热后同配置的成功运行次数 | 超时和失败次数单列，不能伪装成快速成功或静默排除 |
| MODEL-COST | 每个成功样本模型成本 | 完成样本所产生的全部计费调用成本（含失败重试） | 成功完成且产生有效结果的样本数 | 失败样本成本另列为浪费成本；无结果不得进入成功分母 |

比例型指标的 `value = numerator / denominator`。`PERF-LATENCY` 的 numerator 字段保存 P95 毫秒值，denominator 保存成功运行数；原始每次耗时仍需在证据文件中保留。`MODEL-COST` 的 numerator 保存总成本，denominator 保存成功样本数。

## 失败与场景级判定

单个样本运行还应记录 `run_status`：`completed`、`partial`、`failed` 或 `timeout`。任何指标分数都不能覆盖以下硬失败：伪造引用、把不同学期或教学班混用、把缺失日期补成确认事实、隐藏未排任务、移动时间块时改写原始 DDL、部分解析却显示全部成功、删除后继续声称引用可验证。

阈值字段当前统一为 `null`，状态为 `deferred_until_baseline`。首轮至少使用 B010–B012 样本各重复运行并检查切片后，再提出阈值变更；变更记录需包含基线、选择理由、适用版本和批准日期。

## CSV 记录格式

每行表示一次 `run_id × metric_id × slice` 的聚合结果：

- `commit_sha`、`config_id`、`component_version` 固定被测版本；`sample_set_version` 关联登记表快照。
- `slice_key`/`slice_value` 记录 `all`、输入类型或具体边界场景。
- `numerator`、`denominator` 和 `value` 按上表口径填写；`unit` 使用 `ratio`、`actions_per_item`、`milliseconds` 或 `currency_per_sample`。
- `failure_count`、`timeout_count`、`excluded_count` 独立保留，`exclusion_reason` 不得为空白地排除样本。
- `evidence_path` 指向输入清单、逐样本输出和人工复核记录；`notes` 只补充上下文，不改变口径。
