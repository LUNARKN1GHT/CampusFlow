# A016 验证提醒漏发与重复边界

作者：李亦凡；任务 #216；父任务 #21。前置 #213（A015）。

## 覆盖场景

1. **时区变化**：切换工作空间时区后，提醒窗口按新时区重算；旧窗口标记 cancelled，新窗口保留一条待发送。任务 `due_date`／`due_time` 不被改写。
2. **仅日期 DDL**：切换时区后仍只输出日期，正文不出现具体时刻，`due_time` 保持为空。
3. **重复调度**：同一触发窗口连续同步多次，触发记录 id 与数量保持不变；重复间隔产生的多条窗口不会合并或遗漏。
4. **完成重开**：`done` → `in_progress` 后恢复原触发记录，进度历史保留原因；不重复发送已读提醒。
5. **暂停恢复**：规则版本递增，暂停撤消待发送，恢复后只保留一条待发送。
6. **通知变更**：截止更新后旧窗口 cancelled，新窗口唯一，正文使用新截止。

## 修复

- `update_settings` 在时区变化后、提交前调用 `sync_reminders`，避免旧时区触发的记录残留到下一次读取。
