# X001 候选事项与字段证据模型

作者：金嘉睿。叶子任务 #108，父任务 #11。实施次序见 [X 系列路线](../planning/X-IMPLEMENTATION.md)。

## 保存内容

用户选择分开保存，新增三张表：

| 表 | 内容 |
| --- | --- |
| extracted_items | task/event/rule 类型、当前空间、来源版本、适用学期/课程/教学班、核对状态与待核对原因 |
| extracted_fields | 字段分别保存名称、值、出处、说明与缺失原因；同一事项字段名唯一 |
| candidate_field_evidence | 一个字段关联的一个或多个原文片段及摘录；通过真实 SourceChunk 关联原始版本与定位 |

字段值可以是文本、数字或有明确结构的组合值，单字段以 JSONB 保存；整项和证据关系没有塞进一个大 JSON。未知值使用 null 并保存缺失原因，只有日期的原文无需转成带时刻的值。

出处分别是 document（原文规定）、user（用户补充）、inferred（系统推断）、suggestion（规划建议）。原文规定及系统推断的非空值必须有证据；推断/建议必须有说明。出处只表示信息来源，**不表示已经核对正确**。

新候选一律 pending，沿用 ReviewStatus 的 pending/confirmed/ignored/superseded；表内不保存任务执行进度，不接受 done 作为核对状态。本任务不实现状态变更、用户修正历史或转正式任务，这些由 R 系列接入。

## 调用与证据检查

应用层 `save_candidates(repos, workspace_id, material_id, version_no, drafts)` 保存一批候选，`get_candidate` 按空间授权读取；没有开放任意写入候选的 HTTP 接口。后续模型提取调用该保存入口，R 系列可复用存储端口。

保存前核对资料属于当前空间、资料未归档、来源版本存在、关联课程与学期合法，并核对选定资料范围。证据必须来自指定版本中的真实片段，摘录必须是该片段原文子串；不能传入其他版本或其他空间的片段 ID。整批先验证，再在一个事务中写入；数据库失败回滚整批，不留下半成品。

一条候选绑定一个来源版本。不同通知分别保留候选及各自证据，X008 再建立冲突核对关系，不覆盖某个来源的值。合法 ID、原文子串和结构检查并不保证字段语义正确，真实提取准确率由 X010 单独评测。

## 删除与迁移

资料/版本删除会级联清理候选、字段、证据。原有“保留个人任务并标记来源已失效”的行为不变。删除影响 API 新增 candidate_count，页面展示候选数量；确认指纹包含候选 ID 集合，预览后新增候选时旧确认不能继续使用。

新增迁移 `x001_candidate_evidence`，依赖 `n005_web_snapshot_metadata`，仅新增三张表及其索引/约束，保留原有默认空间唯一索引。启动前运行 `uv run --locked alembic upgrade head`。回退该迁移会删除候选表及其中内容，需要保留数据时先备份；不会回退已有任务或资料表。
