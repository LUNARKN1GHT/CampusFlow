# #557 父任务卡片与详情剩余耗时口径一致

对应 Issue：#557。分支：`issue/#557`。

## 问题

任务列表卡片直接显示父任务自身 `remaining_minutes`，而“依赖与子任务”面板显示子任务汇总；完成子任务后出现“卡片 60 分钟 / 详情剩余 40 分钟”的分歧。子任务列表还直接显示 `done`、`not_started` 等内部值。

## 修复

- `GET /api/v1/tasks` 对存在直接子任务的任务返回 `subtask_rollup`，复用 A004 的 `_rollup_from_children`，与 `/tasks/{id}/rollup`、`/tasks/{id}/relations` 同一计算口径。
- 汇总只读，不写回父任务字段，也不改变“排期只安排子任务”的规则；非父任务返回 `null`，原有字段不变。
- 前端卡片在存在汇总时显示“剩余（子任务汇总）+ 完成度”，无子任务时保持原展示。
- 子任务列表的进度改用界面已有的中文映射，不直接输出内部状态值。

## 验证

- `uv run pytest tests/test_subtasks.py tests/test_tasks_api.py -q`：21 passed。
- `uv run ruff check`（改动文件）：All checks passed。
- 前端 `npm run build`（含 `vue-tsc --noEmit`）：通过。
- 新增用例覆盖：父任务自身 60 分钟、子任务 20+40、完成 20 分钟后列表汇总与详情均为剩余 40 / 完成度 33%；普通任务 `subtask_rollup` 为 null；父任务自身字段不被改写。

## 浏览器验证

本机启动后端与 `npm run dev`，登录后通过真实接口创建父任务（60 分钟）与子任务（20+40），完成 20 分钟子任务：

- 任务卡片显示“40 分钟剩余（子任务汇总）”与“完成度 33%”，不再显示父任务自身的 60。
- “依赖与子任务”面板显示“子任务 2 项 · 预计 60 分钟 · 剩余 40 分钟 · 完成度 33%”，与卡片一致。
- 子任务列表显示“整理需求 · 已完成”“绘制流程图 · 未开始”，不再出现 `done` / `not_started`。
