# BUG-554 粘贴文本的保存与识别分开

问题：[#554 粘贴通知后仅保存原文，未进入事项提取与问答准备流程](https://github.com/LUNARKN1GHT/CampusFlow/issues/554)。日期：2026-11-11。

## 问题与结论

粘贴通知后资料显示“完成”，但既没有处理作业，也没有待核对事项。用户因此把“原文保存成功”误认为“通知已经识别、问答已经准备完成”。

按维护者本次要求采用**显式入口**方案，而不是导入后静默调用模型：

- 粘贴仍然只负责保存原文、切分片段与记录适用范围；
- 资料列表与详情明确显示“原文已保存，尚未准备问答／尚未提取事项”；
- 只有用户点击「开始识别」时，才创建问答索引作业并调用文字模型提取任务候选；
- 重复点击不会重复建作业或重复生成候选；未配置模型密钥时在产生任何副作用前返回可读错误。

本项只接入了**任务候选提取**。日程、规则与培养方案提取仍由各自用例支持，但尚未接入本入口；后者需要独立 Issue（见文末）。

## 现状调查

| 链路 | 修改前状态 |
| --- | --- |
| 粘贴文本导入 | `POST /api/v1/materials/text` 同步保存 `.txt` 原文、版本、片段并直接置为 `done`；不创建 `parse` 作业，也不创建 `embed` 作业 |
| 文件上传 | 创建 `parse` 作业；解析成功／部分成功后由 `processing.parse_version` 自动创建 `embed` 作业 |
| 公开网页导入 | 与文件上传相同，解析成功后自动创建 `embed` 作业 |
| 问答索引 | `embed` 作业由现有 RQ／桌面轮询 Worker 执行，状态可在 `/api/v1/jobs` 与 `/api/v1/jobs/{id}/index-progress` 查询 |
| 任务候选提取 | 应用层已有 `application.task_extraction.extract_task_drafts`（X003）与 `save_candidates`（X001），但**没有 HTTP 入口** |
| 日程／规则提取 | 应用层已有 `extract_event_drafts`（X004）、`extract_rule_drafts`（X005），同样没有 HTTP 入口 |
| 培养方案提取 | 唯一已接入 HTTP 的提取入口是 `POST /api/v1/curriculum-plans/{id}/extract`（C003） |

因此“保存后没有待核对项”既不能解释成通知里没有作业，也不是单纯补密钥就能完成：粘贴文本此前没有任何流程会启动提取或索引。本项补上显式触发路径。

此外发现粘贴文本导入没有写入解析覆盖元数据，导致索引即使全部块成功也只能停在 `partial`、永远不能声明完整可检索。本项在导入时写入“文本同步解析、无未覆盖范围”的覆盖记录，使问答准备可以真实到达 `done`。

## 后端实现

### 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/v1/materials/{id}/recognition` | 只读识别状态；不建作业、不调用模型、不写库 |
| `POST /api/v1/materials/{id}/recognition` | 显式开始识别：准备问答索引并提取任务候选 |

两者都要求本机会话，并通过 `get_current_workspace` 限定当前空间；跨空间与资料不存在都按 404 处理。

状态响应（`RecognitionOut`）：

| 字段 | 说明 |
| --- | --- |
| `version_no` / `chunk_count` | 当前版本与已有片段数；原文定位仍由版本片段接口读取 |
| `index.state` | `not_started`／`queued`／`running`／`done`／`partial`／`failed` |
| `index.searchable` | 仅当索引作业 `done` 时为 true，不按资料 `status` 推断 |
| `extraction.state` | `not_started`／`running`／`done`／`empty`／`failed` |
| `extraction.candidate_count` / `pending_count` | 当前版本的任务候选数与其中待核对数 |
| `can_start` / `blocked_reason` | 是否可显式开始，以及归档、来源未切分等阻塞原因 |

`POST` 成功时额外返回 `started` 与中文 `message`。`started=false` 表示识别已完成或正在进行，本次没有重复执行。

### 触发流程

1. 锁定资料行（`materials.lock`）并校验空间、归档状态、来源类型与已切分片段；字段与业务错误在应用层完成。
2. `_index_job_for_start`：同一版本最多一个 `embed` 作业（Q004 唯一约束）；已排队／处理中／已完成保持原样，失败或部分成功才重置，避免重复索引。需要时通过现有 `dispatch_pending_jobs` 投递。
3. 提交索引作业后释放行锁；再锁定资料行检查提取状态。
4. 检查版本元数据 `candidate_extraction` 与已有任务候选：已完成、空结果、已有候选或仍在运行（10 分钟内）都跳过模型调用。
5. 写入 `running` 标记并提交，随后**在事务与行锁之外**调用模型；期间不占用数据库连接。
6. 生成草稿后复用 `save_candidates` 整批保存为 `pending` 候选，并写入 `done`／`empty` 标记；不确认候选、不创建正式任务。
7. 模型或保存失败时写入 `failed` 标记（固定文案，不含异常原文与密钥），用户可再次点击重试。

### 幂等与并发

- **索引作业**：`uq_processing_jobs_embed_version` 保证每个版本最多一个 `embed` 作业；重复点击只复用或补投。
- **候选**：版本元数据记录提取状态；已有任务候选时不重复调用模型；同一版本重复点击不会产生第二批候选。
- **并发**：`SELECT ... FOR UPDATE` 锁定资料行，串行化同一份资料的并发请求；后到请求看到 `running` 标记后直接返回。
- **中断恢复**：`running` 标记超过 10 分钟视为上次进程中断，允许重新开始；模型超时上限远小于该阈值。

### 错误契约

- **未配置模型密钥**：`get_recognition_models` 在产生任务、作业或候选之前返回 400，说明缺少哪个环境变量（如 `ZHIPU_API_KEY`）以及需要先配置并重启服务；不返回密钥内容。桌面端目前从进程环境读取密钥，没有独立的密钥设置页。
- **模型失败**：沿用 Q009 分类，临时故障返回 503，输出无效或请求被拒绝返回 502；正文只说明“本次未保存任何候选事项”，不暴露供应商细节。
- **业务阻塞**：资料已归档、非粘贴文本、来源未切分等返回 400 中文原因；资料不存在或跨空间返回 404。

## 前端实现

资料库页面为粘贴文本增加了独立的识别区块：

- 资料状态为 `done` 时显示「原文已保存」，不再用「完成」暗示整个识别流程结束；
- 显示问答索引与事项提取的真实状态、失败原因、空结果说明与阻塞原因；
- `can_start` 为 true 时显示「开始识别」（失败后为「重新识别」，索引仅排队时提示可重新尝试准备问答）；请求期间禁用按钮；
- 事项完成后显示「去待核对」，索引完成后显示「去问答」；
- 识别进行中纳入现有 3 秒轮询，状态推进后自动刷新；
- 粘贴成功提示明确写“这只是保存，尚未准备问答或提取事项”。

没有自动触发：只有按钮点击才会调用 `POST /materials/{id}/recognition`。

## 验证

使用合成通知与确定性假模型，不调用真实模型网络：

```bash
cd backend && uv run ruff check .                    # All checks passed
cd backend && uv run pytest tests/test_material_recognition.py -q
cd backend && uv run pytest <相关回归套件> -q
cd frontend && npm run build                         # vue-tsc + vite build 通过
```

`tests/test_material_recognition.py`：**8 passed**。覆盖：

- 粘贴只保存原文：无 parse／embed 作业、无候选，状态为“尚未准备问答／尚未提取事项”；
- 显式开始后创建一个索引作业，候选以 `pending` 保存，截止原文可定位验证，不生成正式任务；
- 索引 Worker 完成后状态变为 `done` 且 `searchable=true`；
- 重复点击不重复建作业或候选（`started=false`，模型只调用一次）；
- 缺少模型密钥返回 400、错误含环境变量名且无任何副作用；
- 模型临时故障返回 503、状态标记 `failed` 且可重试；
- 模型明确返回空任务时状态为 `empty`，与失败区分，重复点击不重复调用；
- “下周五提交”保留原文并产生缺年份／相对日期／缺时刻核对原因，不补造日期；
- 已归档资料不可启动识别。

相关回归（作业、索引、问答、资料、候选与删除影响）：**190 passed**。完整后端套件与前端构建结果见提交说明；前端未做真实浏览器交互验收。

## 未完成与后续

- **只支持粘贴文本**：上传文件与网页在解析完成后会自动准备问答索引，但本入口不为其提取任务候选；文件类资料的事项提取需要独立任务。
- **只提取任务**：日程（X004）、规则（X005）提取尚未接入 HTTP，需独立 Issue；当前入口不会静默生成这两类候选。
- **提取是同步请求**：模型调用在请求内完成，没有后台提取作业、队列重试或进度百分比；失败后由用户重新点击。若将来需要长任务或批量提取，应为 `JobStage.EXTRACT` 增加 Worker 入口。
- **未做真实模型与打包验证**：验收使用确定性假模型；未配置真实密钥调用模型，也未在 Windows／macOS 安装包中复测。
- **前端验证范围**：类型检查与构建通过；未执行真实浏览器点击、轮询与移动端检查。
- 原 Issue 中“默认自动处理、允许选择仅保存”的方案未被采用；本实现按本次要求保持显式入口，导入时不会静默调用模型。
