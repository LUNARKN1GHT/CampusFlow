# X006 有依据的相对日期换算

任务：[X006 #113](https://github.com/LUNARKN1GHT/CampusFlow/issues/113)，父 Issue #11。作者：金嘉睿（24151735）。

用户选择代码按明确规则计算，复杂或有歧义的表达待核对。本项不调用模型，不新增依赖、数据库迁移或配置。

## 入口与保存

`application.relative_dates.resolve_task_deadline` 接受 X003 任务草稿、工作空间、资料及版本编号，并由可信调用方显式提供来源时区和当前版本内的发布日期/校历证据。先校验空间、资料状态、版本、候选适用范围及全部引用，再换算；不联网、不写库、不创建正式 Task。

输出保持原 `due_text` 及其核对提示，增加 `due_resolution` 字段，出处为 `inferred`。其值包含 `date`、`time`、`range_start`、`range_end`、`timezone`、`anchor_date`、`anchor_kind`、`rule`、`relation`；`relation=before` 保留原文的“前”，不能默认为当日结束前。原文与依据分别保留真实片段编号和摘录。原文缺年份提示描述的是原文，不能因为推导出年份就删除原文缺失记录。

调用方显式执行 X001 的 `save_candidates` 后，可原样保存及回读结果、规则说明和证据，核对状态仍为 pending。重复换算替换本用例产生的结果与提示，不叠加重复字段；不给依据重新计算时清空旧结果。所有结果都增加人工核对提示，不能根据计算成功自动确认。

## 支持范围

| 输入 | 所需依据 | 结果 |
| --- | --- | --- |
| 今天、明天、后天 | 完整年份的发布日期、明确来源时区 | 发布日偏移 0/1/2 天 |
| 本周五、这周日、下周三、下下周一等 | 同上 | 周一为周首，下一自然周或下下自然周的对应日 |
| 第八周周五、第8周星期五 | 当前适用学期、第一教学周周一和连续计周声明 | 从第一周起逐周计算对应日 |
| 第八周 | 同上 | 一周起止范围；date/time 均为空，不指定某天截止 |
| 明确日期表达后附 18:00、9:05:03 | 同上 | 保留明确时刻；无时刻仅保留日期 |

支持有限的“请于…前提交”“…截止”等外围措辞及全角字符。完整表达必须匹配，单独“周五”、日期区间、多个日期、上午/下午、暂定、取消或未知句式不计算。截止所在原文语句含条件或变更词时，即使短摘录本身有效，也留待核对。

发布日期证据示例：`发布日期：2026年9月28日`、`published_at: 2026-09-28T09:00:00+08:00`。带偏移的发布时间按调用方明确指定的来源时区换算当地日期。日期声明必须完整，不能从“不是发布日期…”截取子串。没有年份、非法日期、非法时区或偏移、夏令时不存在/重复的时刻均不猜测。

校历证据示例：`第一教学周周一：2026-09-07，按自然周连续计数`。必须有明确的连续计周声明，不能假定学校休假周仍然计入教学周；起点须是周一并落在适用学期内，目标周也须完整落在学期内。学期开始日期不等于第一教学周起点。暂停计周、调课或特殊校历不在本有限规则范围内。

## 边界与未交付范围

- 不使用当前日期、导入日期或可变的资料 `published_at` 元数据替代版本内依据；只有元数据而缺少原文声明时保留待核对。本项也不自动识别/选择依据，需要可信调用方或后续核对流程选定。
- 当前依据必须来自同一资料版本。独立校历文件的跨资料授权、引用失效联动及校历管理界面不在本项范围；可以在适用通知原文中明确记录上述校历声明。无范围校验的外部日期参数不能绕过应用入口。
- 不以发布日期推断“10月15日”的年份，也不为日期精度补零点或 23:59。
- 来源时区由调用方根据明确来源或用户核对传入，不从个人偏好、电脑时区或模型猜测回退。该来源关系仍需核对；本项不是自动确定资料适用范围的能力。
- 多条来源互相矛盾的识别留 X008，真实材料提取效果留 X010；所选依据及条件的语义正确性仍需人工核对。
- 未新增 API、自动处理队列入口或页面，也未改变正式任务 DDL。纯领域计算不负责授权，外部调用须经应用入口。
