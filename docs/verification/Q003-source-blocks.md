# Q003 保留原文位置的检索分块

任务 #130；父任务 #13。作者：金嘉睿。日期：2026-10-17。

## 交付与用户选择

用户选择保留已有段落、页面/区域、表格单元的原始边界；过长时优先按句末或换行切开，不合并邻接短段。`build_version_blocks` 复用 D018 的资料归属与版本读取检查，把 D017 已持久化的来源片段交给纯领域算法分块。

- 默认每块最多 3000 UTF-8 字节，对齐 Q002 默认输入上限；无新增依赖、表或模型调用。连续超长句子没有可用断点时按 Unicode 字符切开，不切坏 UTF-8 编码，不截断丢字。
- 默认无重叠；底层支持显式设置 `overlap_chars`。所有块保留 `source_chunk_id`、`version_id`、原始位置、源指纹、起止字符位置和原文切片。重叠只重复同一来源范围，不生成另一份“原文”。
- 块身份由源指纹、起止范围和分块算法版本决定。相同来源和范围重试得到相同身份；同一范围不会因为输入上限不同变成两个身份。原文版本、文本或位置改变后不复用旧身份。
- 同一来源编号出现矛盾内容/定位、同版本顺序冲突或一次混入多个版本都会拒绝；完全相同的重复来源去重。块可通过 `validate_against` 再核验原文范围和身份。
- 保留空白和换行，非重叠分块按顺序拼回后等于输入原文。空字符串无字符可分，返回空列表；纯空白文本仍保留，Q004 调用向量接口前应明确跳过无有效内容的块。表格关系沿用 `table_group`，不推断或补写表头。

## 位置语义与集成边界

`start/end` 是 **Python Unicode 码点索引，左闭右开**，可直接对应 `source.text[start:end]`；不是 UTF-8 字节偏移，也不是浏览器 JavaScript UTF-16 下标。未来前端高亮若使用这些位置，需转换或由服务端返回对应原文切片。

定位直接复制来源的 `locator_type/value`、页码、段落、区域和表格分组；Word 表格单元及网页位置不伪造页码。旧版本块仍绑定旧版本，重分块不修改原文记录。

本项仅产出可追溯检索块，不写索引、不创建公开引用协议、不把部分解析视为完整覆盖。Q004 负责持久化及向量化，Q005/Q008 负责检索状态与失效过滤，Q007 负责对外引用 ID 和候选集检查。后续调用者仍需保留 D011 的失败/未覆盖范围；“有检索块”不能解释为整份资料解析成功。
