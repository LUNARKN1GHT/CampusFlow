# A010 验证提醒规则与触发模型

作者：李亦凡；任务 #182；父任务 #21。前置 A001–A009（E70 依赖与局部重排）。

## 覆盖场景

1. **默认规则**：没有自定义规则时返回内置默认规则（提前 1440 分钟、不重复、不暂停），可以创建一条工作空间默认规则；重复创建返回 409，规则版本随更新递增。
2. **任务规则覆盖**：任务级规则优先于默认规则；两者都按工作空间时区解释触发时间。
3. **重复提醒**：提前量与重复间隔同时设置时，从“截止 − 提前量”开始按间隔生成多个触发窗口，直到截止时刻，不会只保留首尾两条。
4. **仅日期 DDL**：截止只有日期时不补造具体时刻；提醒正文明确“未指定具体时刻”，`payload.date_only=true`，正文不出现时间点。
5. **幂等同步**：重复读取提醒不会产生重复触发记录，`dedupe_key` 唯一约束生效。
6. **已读／忽略**：已读将状态置为 `sent` 并清除未读计数；忽略后重复同步不会重新弹出。
7. **暂停与恢复**：暂停规则会撤消待发送触发；恢复后按新规则版本重新生成。
8. **完成与重开**：任务完成后撤消待发送触发；重开同一任务时，仍有效的已取消触发恢复为待发送，不依赖删除后重建。
9. **删除任务规则**：回落到工作空间默认规则，原任务规则触发的待发送记录被撤消。

## 接口

- `GET /api/v1/reminders`：列出触发记录，可筛选 `status` 与 `unread_only`。读取时先按最新任务与规则同步。
- `GET /api/v1/reminders/summary`：未读、已发送、待发送、已忽略、已取消计数；固定提示“暂无提醒不代表没有待办或冲突”。
- `POST /api/v1/reminders/{id}/action`：`read` 或 `dismiss`。
- `GET/POST /api/v1/reminders/rules`、`PATCH/DELETE /api/v1/reminders/rules/{id}`：规则 CRUD。

## 数据与不变量

- `reminder_rules`：`task_id` 为空表示默认规则；部分唯一索引保证每个工作空间一条默认规则、每个任务一条规则。
- `reminder_triggers`：`dedupe_key` 由任务、规则版本、截止字段和触发窗口生成；迁移 `a010_reminders`。
- 提醒是派生数据：生成失败或撤消失效记录不影响任务本身；任务 DDL 与执行进度不被提醒改写。
- 已发送／已忽略的记录不会被后续同步重新激活；只有仍需要的 `cancelled` 记录会恢复。

## 未覆盖与限制

- 本轮只提供读取时同步，没有独立后台推送进程；应用内提醒中心与规则设置界面由 A015 接入。
- 通知接受、计划变更后的重算由 A014 覆盖；失败重试与并发幂等的更完整验证留 A012。
- 来源资料失效时不会直接删除任务提醒，而是转为待核对提醒；完整判定仍以 R007/N012 为准。
