# A009 验证依赖排期与局部重排不变量

作者：李亦凡；任务 #212；父任务 #20。前置 #207（A008）、#178（N019）。

## 覆盖场景

1. **依赖成环**：历史数据中的三节点环不会被排入，三个任务都出现在未排列表且原因为 `dependency_cycle`，没有静默丢失。
2. **锁定冲突**：接受计划并锁定时间块后，新增重叠固定日程；局部重排保留锁定块原样不动，并在冲突列表同时列出 `plan_block` 与 `fixed_event` 参与方。
3. **耗时增加**：剩余耗时从 60 分钟改为 120 分钟后，调整建议可见；调整草案只排 120 分钟，接受后仍是 120 分钟，没有重复时间块，任务 DDL 不变。
4. **通知变更**：接受后的截止字段变化只触发调整建议；当前计划在接受调整草案前保持原版本；调整草案按新截止安排，接受后任务字段保持通知确认的值，不被计划覆盖。
5. **已完成前置**：前置任务已完成时不参与排期、不再计入耗时，后续任务可独立排入；每个输入任务在草案中恰好出现一次。

## 不变量

- 每个输入任务要么出现在时间块，要么出现在未排列表，不能同时出现或完全消失。
- 同一任务的已排分钟不超过其剩余耗时；容器父任务不参与排期，子任务各自计入。
- 接受局部调整只更新时间块；任务截止、剩余耗时与执行进度保持原值（通知变更本身除外）。
