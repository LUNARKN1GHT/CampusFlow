# N003 Word 正文解析与定位

作者：金嘉睿。任务 #153，前置 N002 #143，父任务 #18。

用户已选择 python-docx。新增 WordDocumentParser 并装配到实际 Worker，复用资料作业状态、片段持久化、重试去重和来源读取接口。新增依赖及 uv.lock 一起提交。

- 正文按段落和表格实际顺序解析；空段落不输出文本，但保留其位置编号。
- 普通正文使用从 1 开始的段落号；表格按遍历顺序编号，单元定位为 `t1:r3:c2:p1`（表格 1、行 3、列 2、单元内段落 1）。嵌套表格独立编号，合并单元格只引用首次出现的左上位置。
- 片段绑定原有 version_id，因此不同版本的同一段落号不会共用引用身份；不伪造页码。
- 图片、文本框、嵌入对象以及修订、内容控件、页眉页脚脚注等未覆盖范围明确列为失败范围，已有文字仍可部分成功。空文档不标记成功。
- 原文可经已有授权接口下载为正确 DOCX 类型。没有新增资料页面；本任务覆盖上传 API→Worker 用例→定位片段和原文读取。

验证：N001 段落/表格预期、合并与嵌套表格、空段落和空文档、图片未覆盖提示、真实数据库上传到解析闭环、重复作业不重复生成片段。运行 `pytest tests/test_word_parser.py -q`；完整检查结果附 PR。

解析行为依据 [python-docx 表格说明](https://python-docx.readthedocs.io/en/latest/user/tables.html)，页码不由该库计算。生产 Worker 保持现有 Docker 启动方式；仅 Word 的测试不调用视觉模型。
