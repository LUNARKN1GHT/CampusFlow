# N010：资料版本关联与替代声明

任务 #145，父任务 #19。作者：金嘉睿。用户选择单独保存关联记录，原文件、片段与引用保持原位。分支 `issue/#145` 基于父分支 `issue/#19`；父分支从最新 `develop` 的 `706251c` 建立，不混入待审核的 Q004/Q009。

## 已实现的范围

- `material_version_relations` 保存两个版本的关联、用户填写的依据、操作者、记录时间及两端发布信息/适用范围快照。两个版本可以属于同一资料，也可以属于同空间的两份独立资料。
- `same_source` 表示用户声明同源，编号顺序规范化，反向重复提交也只保存一条。
- `replacement_claim` 表示当前 URL 指定的版本**声明替代**请求体中的目标版本，方向由用户明确选择。发布时间、版本编号和导入顺序都不替用户选择生效版本。
- 关系是用户补充，`origin=user`、`review_required=true`、`replacement_effective=false`。记录替代声明不等于接受替代，不改原版本、正式任务/规则、日程或后台处理的目标版本。接受变更属于 N014，完整冲突判断属于 N012，关系对照/接受界面属于 N017。
- 当前学期、课程、班级逐字段比较：已知字段不同返回 `different`，没有已知差异但有空缺返回 `unknown`，全部明确且相同才返回 `same`。空字符串/全空白也算未知，未知不是“适用于所有人”。不同或未知范围的声明只能作为待核对记录，不直接替代。
- 每条记录保存关联当时的资料元数据（标题、发布人、发布时间、范围），版本原有 `publisher/published_at/published_text` 另存于 `version_publication`。前者是**关联时快照**，不冒充文件最初发布时的历史真相。未知发布时间保持 null，日期原文保留原样，不补年份或午夜，不拿导入时间当发布时间。
- 后续修改资料元数据不会覆盖已存快照；读取重新核对两端范围，返回 `metadata_changed` 及归档标记。归档资料可查看原关联，但不能新建关联，恢复后可再次建立。

## 接口

接口均要求登录和工作空间授权。版本编号使用 `GET /api/v1/materials/{material_id}/versions` 返回的 **id**，不是列表内的 `version_no`。

```http
POST /api/v1/material-versions/12/relations
Content-Type: application/json

{
  "target_version_id": 8,
  "kind": "replacement_claim",
  "statement": "课程群中的修订通知声明替代原作业说明，等待核对。"
}
```

这表示 12 声明替代 8。同源关联可改用 `kind=same_source`。首次返回 201，完全相同的重复声明返回同一记录及 200；同一关系已有不同依据说明时返回 400，不能通过重发请求覆盖旧依据。操作者来自登录会话，请求不能伪造 actor 或传 accepted 等状态。

`GET /api/v1/material-versions/{version_id}/relations` 查询涉及该版本的双向关联。不存在或其他空间的版本返回 404；读取再次核验两端空间，不返回其他用户的发布信息快照。输出不包含文件存储路径、校验和或私有正文。

N010 没有编辑/接受声明接口。用户错误声明的撤销与接受历史需要在后续变更流程中处理，不以改写数据库代替可追溯纠错。

## 并发与删除

同空间关系创建先锁空间，再锁两端资料/版本，数据库唯一约束保证重复请求只创建一条。事务由应用用例提交，失败整体回滚，无模型请求。

删除任一端资料会级联移除关系记录，不删除另一份资料或它的原文。删除影响接口增加 `version_relation_ids`，页面提示将删除的关联数，确认指纹包含这些编号。确认到执行期间持有资料锁，防止并发新建关系绕过删除确认；关系先建立则旧确认失效，资料先删除则新建关系失败。
