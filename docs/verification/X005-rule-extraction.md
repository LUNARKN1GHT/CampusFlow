# X005 课程规则候选提取

任务：[X005 #112](https://github.com/LUNARKN1GHT/CampusFlow/issues/112)，父任务 #11。作者：金嘉睿（24151735）。2026-10-14。

## 用户决定与接口

用户选择“完整原文＋单列条件”，不让模型精简改写规定。继续使用 X002 智谱文字接口及 X001 候选/字段/证据表，无新增依赖、迁移或配置。

`application.rule_extraction.extract_rule_drafts(repos, workspace_id, material_id, version_no, generator)` 先授权、验证来源版本，再生成和核验规则草稿。无规则返回空列表；任一候选无效则整批报错，不返回部分结果。函数不写库、不创建任务或日程，不自动更新已有规则。调用方可显式使用 `save_candidates` 保存，状态仍为 pending；确认及正式规则查询由 R006 等后续用例负责。

| 字段 | 内容及限制 |
| --- | --- |
| title | 规则名称原文，必须包含于 rule_text；仅作标题，不能替代正文 |
| rule_text | 完整原文片段，保留所有条件、否定、例外和限定；必填 |
| conditions_text | 条件与例外的完整原文语句；未明确则 null 和原因 |
| scope_text | 课程、班级、对象等适用范围的完整原文语句；未知则 null |
| effective_text | 生效/失效信息完整原文语句，不换算日期；未知则 null |

所有字段为 document，禁止模型以推断或建议冒充规定。每个非空字段必须关联自身真实证据；正文和辅助字段分别记录证据，允许范围和生效声明来自当前版本的其他片段。

## 条件完整性检查

- `domain/rule_extraction.py` 要求 rule_text 与一个被引用片段的全文相同，仅忽略首尾空白。即使“进入实验室”存在于原文，也不能从“通过培训后才能进入实验室”中截出来冒充完整规定。
- 同片段的多句说明和第二句例外全部保留；同一片段有多条规定时可共享完整正文、用原文标题区分。
- 条件、范围、生效信息必须在完整语句边界截取。逗号和分号不作为边界，避免丢掉关联条件或否定；句号、问叹号和换行可作为边界。
- 缺失字段由程序补充 `missing_<字段名>`。每条规则补充 `rule_context_review`，要求一并核对完整规定与限定信息；模型不能以同名提示覆盖这些原因。未知条件不等于“无条件”，未知范围不等于“所有人”。
- 仅有发布时间、上传或导入时间而没有生效声明时，拒绝当作 effective_text；“自发布日期起生效”可保留原文，但不换算为日期。

检查保证已选择片段不被截断改写，不保证模型找全其他片段中的全部条件，也不能证明所选范围一定适用于该规则。跨片段关联、漏提取、分类和语义支持程度仍需 X010 实测及人工核对。标题或辅助字段不得脱离 rule_text 独立作为确定事实展示。
