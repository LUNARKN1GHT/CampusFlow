# N002 Word 格式与大小校验

作者：金嘉睿；任务 #143；父任务 #18。

用户选择先支持普通 `.docx`。旧 `.doc`、宏 `.docm` 和模板须另存为普通 `.docx`。复用 `/api/v1/materials/upload`、私有文件存储、工作空间授权和重复文件检查。

上传前检查文件总大小（沿用默认 20 MiB）、ZIP 校验和、Word 内容类型、主文档关系和 XML 结构；拒绝加密、宏、重复条目、非法内部路径和 DTD。只在内存读取，不解压到磁盘。包内最多 2000 个项目，解压总量最多 64 MiB，单个 XML 最多 8 MiB。

校验失败不保存原文、不创建资料和作业；数据库建档失败时回滚并移除已保存原文。有效文件标记为 `word`，保留原有队列流程。正文解析与 Word Worker 适配由紧随其后的 N003 完成；不要将仅完成校验的本提交当作完整 Word 导入已验收。

验证：`pytest tests/test_word_upload.py -q` 覆盖 N001 真正的 DOCX 样本、伪造文件、损坏结构、不支持格式、压缩包大小边界、真实上传与事务失败清理；完整 pytest、Ruff 和前端构建结果附 PR。

基础同步包含 J009 的资料处理整合代码（PR #326 尚待评审），以及 develop 的 M1 修复。评审须区分既有基础同步提交与本任务独立功能提交；合并本任务前应核对前置整合评审。
