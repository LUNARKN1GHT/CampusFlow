# Q002 向量生成与不可变配置记录

任务 #129；父任务 #13。作者：金嘉睿。日期：2026-10-17。

## 交付

沿用 Q001 的智谱 Embedding-3（1024 维）。用户选择独立保存不可修改的模型配置。`embedding_profiles` 保存供应商、型号、本地索引代次、维度、生成设置、创建时间；这是全局配置目录，不存密钥、原文或工作空间内容。

- 完整配置规范序列化后取 SHA-256 作为编号；改型号、代次、维度或设置都会产生新编号。重复登记使用数据库冲突保护，不重复建记录；数据库触发器拒绝 UPDATE/DELETE。
- 每个 `EmbeddedText` 必带配置编号及返回型号。`embed_registered_text` 先检查已登记配置与适配器一致，再显式调用并核验结果。`cosine_similarity` 拒绝不同配置的向量，即使维度相同。
- 固定官方 HTTPS 地址，禁止跳转；单次一段，原文不清洗、不截断。上限 3000 UTF-8 字节，超出交由 Q003 分块；上限也是配置身份的一部分。响应最多 256 KiB，严格校验条目数、索引、型号、维度、有限数字、非零向量和重复 JSON 键。
- HTTP 408/429/5xx、超时与连接中断归为可重试错误；其他拒绝和无效响应不当作成功。错误不带密钥、原文及上游响应正文。没有自动重试或隐式模型降级；调用者可显式重试，Q009 统筹限额与降级。

## 使用与边界

先在事务中调用 `SqlEmbeddingProfiles(session).register(embedder.profile)` 并提交，再通过 `embed_registered_text(repository, embedder, profile_id, text)` 显式生成。仓储不自行提交其他业务修改；`build_embedder(Settings(...))` 只构造，不联网。Q004 负责在已授权范围内调用、保存向量与配置外键、有限重试及幂等写入。

`revision=q001-v1` 是本地索引代次，**不是供应商内部模型版本的证明**。回显型号不能检测供应商在同一别名下静默升级；已知升级后须提升代次并重建索引。Q004/Q005 必须在真实数据库检索入口用同一配置编号过滤，不能只比较维度。本任务不包含线上索引、检索 API、页面或自动 Worker 接入。

超时设置是底层网络等待上限，不是整个任务的严格墙钟时限。可重试不意味着失败请求未计费。本次使用模拟响应，不读取真实密钥、不产生模型费用，也不外发真实课程资料。
