# N017 版本对照与变更接受界面

作者：李亦凡；任务 #173；父任务 #19。前置 N014 #168、D020 #104。

## 已实现

新增 `/review/changes`「版本对照」页面（导航入口「版本对照」）：

- 选择基准（旧）与待比较（新）候选，显式加载对照。
- 并列展示两侧资料标题、版本号与学期/课程/教学班，先让用户确认版本适用范围。
- 字段表展示每个差异的旧值、新值、状态与两侧原文摘录、定位和可验证状态。
- 展示 N012 适用性结论与原因、N013 受影响任务/时间块（含已完成与锁定项）及提醒/外部日历未接入说明。
- 用户勾选要接受的字段、填写原因；冲突/待核对时需勾选“我已核对冲突并确认接受”。点击接受调用 N014，未点击前页面不发送写请求，当前安排不变化。
- 接受后展示结果；历史区列出旧/新版本、原因、操作者与逐字段证据快照。

## 验收对照

| 验收条件 | 证据 |
| --- | --- |
| 用户能识别版本适用范围 | 两侧版本卡片同时展示标题、版本号、学期/课程/教学班与发布时间；Playwright 断言范围文本可见。 |
| 未接受时当前安排不变化 | 加载对照只调用只读 diff/applicability/impact/history；Playwright 统计接受请求，在点击按钮前为 0；只有点击后才提交所选字段、原因和冲突确认。 |

## 验证

```text
frontend$ npm run build

✓ vite build

frontend$ npx playwright test tests/e2e/version-change.spec.ts
```

Playwright 用固定 API 响应验证界面逻辑，不修改真实数据。后端判定、影响查询与接受事务分别由 N012/N013/N014 的测试覆盖。

## 未覆盖与限制

- 页面不做自动配对，用户必须显式选择两个候选。
- 接受只更新候选版本状态与历史；正式任务/时间块的调整仍由用户按 N013 影响清单处理。
- 未接入提醒与外部日历，界面明确显示未同步。
