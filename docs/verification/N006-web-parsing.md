# N006 网页正文提取与原始定位

作者：金嘉睿；任务 #159；父任务 #18。依赖 N005 #154 与 D011 #87。

用户选择 Beautiful Soup，依赖及版本写入 pyproject.toml / uv.lock。联网仍由 N004 的标准库实现；本解析器只读取 N005 已保存的字节，不重新抓取，不执行 JavaScript，也不访问图片、嵌入对象或登录表单。接口用法见 [N005](N005-web-snapshot.md)，Worker 启动见 [资料处理说明](../MATERIAL_PROCESSING.md)。

## 已实现的链路

受保护的网页导入请求 → N004 公网抓取 → N005 私有快照及版本来源记录 → 待处理作业 → Worker 的 WebDocumentParser → 原文片段及状态。

正文优先选 article、main 或常见正文容器，否则从 body 提取。删除导航、侧栏、页脚、脚本、表单、明确隐藏元素及常见广告/菜单标记；保留标题、段落、列表、表格单元和通知页眉的发布信息。嵌套表格独立分组，不重复提取单元格中的段落。页面布局判定采用规则，不能保证覆盖所有网站；只验证已列出的合成样本，不宣称任意学校网页都能正确提取。

解码优先使用快照保存的 HTTP charset，其次 HTML meta charset，没有声明时按 UTF-8 读取。声明无效或字节不符合编码时明确失败，不静默生成乱码。纯文本网页按空行切段；不凭字符猜测发布时间。

## 如何返回原始版本

片段仍通过 `GET /api/v1/materials/{id}/versions/{version_no}/chunks` 读取，带有 `version_id`、`locator_type`、`locator_value` 和原文。HTML 的位置类型为 `web`，位置值如 `p:3`，含义是**保存的原始 HTML 经 html.parser 解析后的第 3 个 p 元素**，序号从 1 开始。编号发生在清洗之前，菜单被过滤不会导致后续段落位置改变。表格单元使用 `td:N` / `th:N`，并带 `web-table-N` 分组。

N001 网页样本“正文第 2 段”对应原始 `p:3`，因为页眉发布信息占原始 `p:1`。发布信息本身也保存为片段；字段没有用户提供的发布时间时仍为 null，绝不用考试日期或抓取日期替代。

读取片段对应的版本后，使用该版本原文下载入口 `/api/v1/materials/{id}/versions/{version_no}/file`；用相同解析器对下载快照执行 `find_all(tag)[number - 1]` 即可找回原始元素。旧网址后来改变或重新导入，不会改写旧文件、旧片段或旧位置。纯文本网页的位置类型为 paragraph；无标签的 HTML 文本退回整个 document 的范围，不伪造元素。

这是后端定位契约，点击高亮/预览页面由后续前端任务接入。HTML 仍按受保护附件下载，不为预览而解除同源脚本限制；页面不得直接把下载 HTML 注入应用。

## 失败与未覆盖范围

- 识别到密码输入或登录表单：不生成正文片段，作业/资料显示失败，提示上传或粘贴原文。对带有登录表单的公开页面采取保守拒绝，未实现任意登录门户识别。
- 正文内图片、音视频、SVG、嵌入对象：记录对应原始元素未识别；有文字则部分成功，没有文字则失败。不自动 OCR 或下载链接附件。
- 空正文/纯动态页面：失败；只有页眉可读而 main 为空时显示部分成功，并明确正文未读取。
- 所有来源缺失、删除后迟到作业、幂等执行和重试规则复用既有资料作业用例。
