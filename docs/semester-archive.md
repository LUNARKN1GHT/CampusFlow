# 学期归档与历史查询（W009）

归档不是删除、取消任务或只读锁定。`PATCH /api/v1/semesters/{id}` 的 `archived` 只更改学期标记，`false` 恢复。重复设置同一值幂等；课程、任务、DDL、进度历史、日程与可用时间不变，恢复不重新创建记录。

## 当前与历史范围

- `GET /semesters` 是进行中学期入口，默认不含已归档学期；`include_archived=true` 返回全部学期，标记区分当前和历史。日期已过不自动归档。
- `/courses`、`/tasks`、`/fixed-events` 默认返回当前空间的全部记录，包括历史。特别是任务不会因学期归档静默消失；总览／待办仍可以看到未完成的历史任务。
- 上述三个列表和 `/fixed-events/occurrences` 均支持 `semester_id`。通过课程关联到该学期，当前和已归档学期使用相同规则；未关联课程的个人任务／日程只出现在未指定学期的查询中。任务的 `course_id`、`progress` 与 `semester_id` 取交集。
- 指定不存在或不属于当前空间的学期统一返回 404，不泄露其他空间的信息；仍保留所有原有对象级授权。归档后的对象详情和修改接口仍可用。
- 课程页默认隐藏历史学期入口，勾选“显示历史学期”可选择课程与恢复；关闭历史显示后不继续停留在历史课程。任务页的全部学期包括历史，并明确标注归档学期。

## 资料边界

父 Issue #5 的资料管理尚未实现，当前不声称已有资料查询／归档接口。后续资料模块应遵循同一非删除语义：学期归档不删原文件、版本、来源、引用或派生记录；在当前工作空间内允许按历史学期显式查询。资料自身的归档／删除状态与学期标记独立，删除影响继续按 README 与 AGENTS 的确认协议处理，不自动级联。该规则不代表 #8／#9 的资料集成已经验收。

## 回归依据

`backend/tests/test_semester_archive.py` 验证归档、重复归档、恢复、课程／任务／日程范围一致、任务详情和进度历史不变、可用时间不变、筛选交集、未关联事项与跨空间／不存在学期的拒绝。浏览器手动管理流程验证历史入口、课程查看、恢复与任务保留。父级集成仍需在全部子项汇总后验证。
