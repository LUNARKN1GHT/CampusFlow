# 问答界面设计说明（Q016 / Q017）

配套原型：[qa.html](qa.html)（浏览器直接打开，可切换回答状态示例）。本文把验收条件映射为交互规则，并给出对 M4 后端任务（Q012–Q014、Q008）的接口期望。两个 Issue 的实现仍依赖后端完成，本文档不构成 Issue 关闭依据。M0 原型 `review-qa.html` 的问答区覆盖了单轮三种回答形态，本文聚焦其未覆盖的连续追问、引用卡片交互、加载失败区分与来源失效提示。

## Q016 问答页面和引用卡片（#151）

| 验收条件 | 交互规则 |
| --- | --- |
| 点击引用定位原文 | 回答内联引用编号与右侧引用卡片均可点击，跳转原文定位视图（复用 D020），按引用 ID 定位页码 / 区域 / 段落 |
| 加载失败和无依据状态独立展示 | “加载失败”（检索服务不可用，可重试）与“无依据”（资料不足，不生成引用）是两种独立状态，文案与引导动作不同：前者重试，后者引导导入资料 |

其他规则：每条回答固定展示覆盖范围说明（检索了哪些学期、教学班与资料）；连续追问保留上下文并标注“追问 · 依据同一资料”；引用卡片展示摘录、来源标识、位置与适用范围。

对后端的期望：

- 问答接口返回回答文本、结构化引用列表（引用 ID、摘录、来源标识、定位数据、适用范围）与覆盖范围描述；
- 无依据回答返回明确的空引用列表与缺失说明，不返回占位引用；
- 检索失败返回可区分的错误码，前端据此渲染加载失败态而非无依据态。

## Q017 来源失效与回答覆盖提示（#156）

| 验收条件 | 交互规则 |
| --- | --- |
| 旧回答不会继续显示已删除来源可验证 | 历史回答中的引用卡片按来源当前状态渲染：来源删除后徽标变为“已失效 · 资料删除”并附失效时间，回答上方提示结论需重新核对；任何时候不展示“失效来源仍可验证” |
| 用户可进入核对或导入资料 | 失效与冲突提示固定提供两个出口：前往待核对（复用 R008 队列，定位到对应候选项）、导入替代资料（复用 D019 导入入口） |

其他规则：所引资料存在未识别区域时，回答固定提示“回答可能不完整”并可查看未覆盖范围；存在未确认的冲突版本时回答不采用任何一方。

对后端的期望：

- 引用状态实时查询：按引用 ID 返回 `valid` / `expired`（含失效原因与时间），会话加载历史回答时批量刷新引用状态；
- 回答关联的未识别范围与冲突标记随回答返回，前端按标记渲染对应提示与入口。

## 对前端的依赖

- 复用 U002 统一 API 客户端的错误处理；路由建议 `/qa`；
- 引用跳转复用 D020 定位视图与 R008 待核对入口；待核对冲突与导入资料入口分别跳转 `/review` 与 `/library`。
