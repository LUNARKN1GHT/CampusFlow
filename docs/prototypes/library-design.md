# 资料库界面设计说明（D019 / D020 / D021）

配套原型：[library.html](library.html)（浏览器直接打开，可切换各状态示例）。本文把三个 Issue 的验收条件映射为交互规则，并给出对后端接口的期望，供 M2 后端任务（D003–D005、D007、D009、D010、J006）对齐。三个 Issue 的实现仍依赖后端完成，本文档不构成 Issue 关闭依据。

## D019 资料库上传与处理状态（#103）

| 验收条件 | 交互规则 |
| --- | --- |
| 部分成功显示未覆盖页面区域 | 状态为部分成功的资料在列表行内直接展开未覆盖范围（页码 / 截图区域 / 文本段落），文案明确“缺失内容不会被当作没有要求” |
| 上传结果与后台实际状态一致 | 列表状态只允许来自后端状态查询，不做本地乐观推断；处理中的条目轮询刷新，重试后回到“待处理 / 处理中” |

状态枚举（与 J006 作业状态对齐）：`待处理 → 处理中 → 完成 / 部分成功 / 失败`，失败条目展示失败原因与“重试处理”入口。

对后端的期望：

- 资料列表接口按条目返回状态、失败原因、未覆盖范围的结构化描述（页码区间 / 坐标 / 段落序号）；
- 重试接口幂等：同一资料重复重试不产生重复作业，返回当前作业状态。

## D020 原文定位视图（#104）

| 验收条件 | 交互规则 |
| --- | --- |
| 三种输入均能核对原文 | PDF 高亮页内坐标区域；图片高亮截图区域；粘贴文本高亮段落序号。侧栏固定展示稳定引用 ID、位置、坐标与适用范围 |
| 引用失效时显示原因而不假装仍可验证 | 失效态不渲染原文，只显示失效原因（删除 / 版本替换）、失效时间和受影响事项数量，并引导至待核对 |

对后端的期望：

- 定位接口按引用 ID 返回类型（pdf / image / text）、定位数据（页码 + 坐标 / 区域坐标 / 段落序号）与适用范围；
- 引用失效时返回明确失效原因码（如 `source_deleted`、`source_replaced`），前端按原因码渲染文案，不自行猜测。

## D021 资料归档删除交互（#105）

| 验收条件 | 交互规则 |
| --- | --- |
| 只执行展示过的删除范围 | 删除前固定展示影响预览：失效候选数、需重核事项数、不可验证引用数、个人任务保留选择、备份保留期限；确认按钮文案绑定该范围，内容变化后需重新确认 |
| 失败后不显示删除成功 | 删除结果以后端逐项结果为准；任一步骤失败整体显示“删除未完成”并说明仍可访问，重试不重复已成功部分 |

归档与删除区分：归档可恢复，退出检索与问答但引用保留并标注；删除按 AGENTS.md 覆盖检索索引与派生内容。

对后端的期望：

- 删除前提供影响预览接口（按资料返回关联事项 / 引用 / 任务计数），删除请求需携带预览版本或范围摘要，与最新内容不一致时拒绝执行（与 M9 确认一致性规则同源）；
- 删除接口返回逐项结果（原文件 / 解析结果 / 索引 / 引用标注），支持只重试失败项；
- 归档、恢复为独立接口，恢复后引用重新生效。

## 对前端的依赖

- 复用 U002 统一 API 客户端：401 跳登录、404 与 409 文案、网络失败重试提示均已具备；
- 三个视图同属“资料库”页面，路由建议 `/library`，列表行点击进入定位视图，归档删除在详情操作区。
