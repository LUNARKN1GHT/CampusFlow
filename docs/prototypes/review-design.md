# 核对界面设计说明（R008 / R009）

配套原型：[review.html](review.html)（浏览器直接打开，可切换操作反馈与确认结果示例）。本文把验收条件映射为交互规则，并给出对 M3 后端任务（R001–R006）的接口期望。两个 Issue 的实现仍依赖后端完成，本文档不构成 Issue 关闭依据。M0 原型 `review-qa.html` 已覆盖队列与字段修正的基本形态，本文聚焦其未覆盖的来源标注与操作反馈；R009 的确认结果反馈部分随 #126 任务补充。

## R008 集中核对列表与详情界面（#125）

| 验收条件 | 交互规则 |
| --- | --- |
| 用户可以从待核对入口处理全部候选 | 待核对是独立页面与队列入口，覆盖全部候选；处理完一项自动前进到下一项，不依赖聊天记录 |
| 核对错误不会被成功提示掩盖 | 操作反馈逐动作就地展示（保存失败、部分失败各自独立横幅），不用全局成功提示覆盖失败；部分失败时已完成与未完成的部分分别说明 |

字段级来源标注：每个候选字段标注 `原文规定` / `用户补充` / `系统推断`（对应 AGENTS.md 来源规则）；系统推断（如预计耗时）可编辑但不参与核对结论。详情区固定展示原文片段与定位入口（复用 D020 定位视图）和未覆盖范围。

对后端的期望：

- 候选列表接口返回状态标签（日期缺失 / 来源冲突 / 部分识别等）与摘要，支持按课程、学期筛选；
- 候选详情接口逐字段返回值与来源类型（`source` / `user` / `inferred`）、原文引用 ID、未覆盖范围描述；
- 保存修正与确认、忽略为独立接口，各自返回明确成败，前端不把批量结果合并成一条提示。
