# CampusFlow 课程项目 PRE

对应 Issue：V008（#389）。状态：**讲稿与演示脚本已完成，API 级技术走查通过；作者决定不单独执行完整界面彩排（2026-11-11），以技术走查与自动化流程覆盖替代**。

## 1. 一句话定位

CampusFlow 把分散的课程资料整理成“有原文依据、经过人工核对、可以执行”的学习安排：
导入资料 → 提取与核对 → 带引用问答 → 两周计划 → 更新进度。

## 2. 演示前提

- 只用合成样本，不使用真实课程资料、群聊截图或个人信息。
- 主线只演示已在 M5 及后续发布中验证的能力；未验证项放在“已知限制”，不当作已交付。
- 智能问答、待核对、版本对照与外部日历的前端页面自 2026-11-12 起暂未提供入口，
  后端接口与验收记录保留。涉及这些页面的步骤按第 4.2、4.3 节改为现状说明，
  不再要求现场点击不存在的页面。
- 模型能力需要有效密钥。演示前按「设置 → AI 服务」（桌面版）或环境变量配置；
  保存后文字问答立即生效，后台资料处理需重启应用。
- 若现场无法调用模型，使用预设已处理数据与录屏兜底（见第 7 节）。

### 合成样本

资料标题：`【合成】数据库原理 测试1班 实验报告通知`

正文（可直接粘贴）：

```text
【合成】数据库原理，测试1班：
实验报告请于 2026-12-18 18:00 前提交，提交方式为课程平台上传 PDF。
报告需包含需求分析、E-R 图、关系模式与查询语句。
迟交每天扣 10%，逾期三天不再接收。
任课教师：合成教师。
```

说明：日期、课程、班级、教师均为虚构；不包含真实校务信息。

## 4. 演示主线

### 4.1 导入资料（约 1.5 分钟）

1. 打开「资料库」，选择学期／课程／教学班，点击「导入资料」→「导入文本」。
2. 粘贴上面的合成通知，填写标题，保存。
3. 预期结果：
   - 资料行显示“原文已读取”和“问答索引未开始”，明确“原文保存完成”不等于“已经能问答”。
   - 粘贴文本不会自动调用模型或建立索引。
4. 点击「查看原文」，展示分段与原文定位；指出后续引用会回到同一版本和片段。

证据：`docs/verification/BUG-554-paste-text-flow.md`、`docs/verification/BUG-555-material-status.md`。

### 4.2 保存与识别分开（约 2 分钟）

1. 在资料行点击「开始识别」。
2. 预期结果：
   - 系统为当前版本准备问答索引，并提取任务候选；
   - 失败时显示原因与重试入口，不伪造“已完成”；
   - 重复点击不会重复建作业或重复生成候选；
   - 行内只显示识别状态与候选数量，候选不会被当作已确认要求。
3. 说明现状：待核对页面自 2026-11-12 起暂未提供前端入口。候选、逐字段修正与确认转换的
   后端接口保留（R008、R009 验收记录仍有效），但现场不再要求进入该页面点击。
4. 切换到「任务」页，用新建任务手动录入同一要求（截止 2026-12-18 18:00、预计 120 分钟），
   保证后续计划演示有正式 DDL；说明页面恢复后可改由候选直接生成，不必重复录入。
5. 预期结果：手动任务不携带资料来源与引用；页面恢复后从候选生成的任务才会记录来源，
   资料删除时来源标记失效，个人任务保留。

证据：`docs/verification/R008-review-workbench.md`、`R009-review-actions.md`、`BUG-554-paste-text-flow.md`。

### 4.3 带引用问答（约 1.5 分钟，页面暂未提供）

智能问答页面自 2026-11-12 起暂未提供前端入口，问答接口、引用校验与会话能力保留，
Q016／Q018 的验收记录仍有效。本节改为现状说明，不打开不存在的页面：

1. 说明回答结构：正文与引用分开返回；无候选时不调用模型，使用“现有资料中没有找到”；
   冲突并列展示，不按导入时间择一。
2. 打开 `docs/verification/Q016-qa-page.md` 与 `docs/verification/Q018-acceptance.md`，
   展示引用可定位到资料库的版本与片段的验收记录与截图。
3. 说明“实验报告什么时候交？提交方式是什么？”这一问在页面恢复后的预期答案与边界，
   现场不对该问题点击作答。
4. 回到资料库「处理详情」，展示每份资料的问答索引状态与失败原因，说明索引准备好与否
   可以核对，但问答入口要等页面恢复。

证据：`docs/verification/Q016-qa-page.md`、`Q018-acceptance.md`、`Q007-citations.md`。

### 4.4 两周计划（约 2 分钟）

1. 打开「任务」页，确认刚才生成的任务带有正式 DDL 与剩余耗时。
2. 进入「学习计划」，选择“未来两周”，生成草案。
3. 预期结果：
   - 固定日程、截止时间与依赖优先；
   - 展示安排理由、未排入任务与预计缺口；
   - 冲突区分确定冲突与基于耗时估计的风险。
4. 点击接受计划，说明草案接受后才成为当前计划；编辑时间块不会修改课程 DDL。

证据：`docs/verification/M5-acceptance.md`、`A007-planning-ranges.md`、`A009-dependency-acceptance.md`。

### 4.5 更新进度（约 1 分钟）

1. 回到「任务」，打开父任务的「依赖与子任务」。
2. 将 20 分钟子任务标为已完成。
3. 预期结果：
   - 父任务卡片与详情都显示子任务汇总：剩余 40 分钟、完成度 33%；
   - 排期只安排子任务，不重复计入父任务耗时；
   - 进度历史保留原因。

证据：`docs/verification/BUG-557-task-rollup-display.md`、`A004-subtasks.md`。

## 7. 兜底材料

现场环境异常时按顺序切换：

1. **模型 API 不可用**：切换到已提前处理好的备份工作空间（索引与计划均已生成），
   只演示计划与进度，并用验收记录说明问答与核对结果；明确说明这是预生成数据。
2. **后台 Worker 不可用**：使用已完成资料；或直接演示计划页面，不现场等待队列。
3. **桌面版异常**：改用本机开发构建的浏览器界面；说明安装包与开发构建共用同一套前后端。
4. **网络中断**：本地功能（资料、任务、计划、提醒、导出）仍可用；模型能力明确失败，不伪造结果。

## 9. Q&A 预案

**问：如何避免模型编造？**
答：答案必须带候选集内引用；日期还要核对是否出现在被引原文；无候选时不调用模型并使用固定缺省文案；
冲突并列展示，不按导入时间择一。

**问：资料会不会被发到外部模型？**
答：演示只用合成样本。真实资料是否发送取决于模型供应商条款与用户配置；条款澄清前不发送真实校务资料。

**问：为什么粘贴后不能直接问答？**
答：保存与识别分开，避免在用户不知情时调用模型；点击「开始识别」后才准备索引与提取事项。

**问：计划会不会改课程 DDL？**
答：不会。计划只移动个人学习时间块；正式 DDL 来自任务字段，调整时间块不修改原始截止。

**问：桌面版和 Docker 版关系？**
答：同一套后端与前端；桌面版用 Electron 外壳、内置 PostgreSQL 与 sidecar，不依赖 Docker/Redis。
安装包未签名，真实干净机器验收仍在进行。

### 10.1 API 级技术走查（2026-11-11）

目的：在无模型密钥的隔离环境验证脚本中的非模型路径与预期输出，不替代界面彩排。

- 环境：独立测试库 `campusflow_pre_test`，server 模式，未配置 `ZHIPU_API_KEY`。
- 步骤与结果：
  1. 创建学期／课程／可用时间，粘贴第 2 节合成通知。
  2. 资料列表返回 `text_state=ready`、`index.state=not_started`，提示“粘贴文本目前不会自动建立问答索引”。
  3. 点击「开始识别」对应接口返回 400：`缺少 ZHIPU_API_KEY，不能调用真实向量模型；请在环境变量 ZHIPU_API_KEY 配置后重启服务并建立索引`。没有创建候选或伪造成功。
  4. 创建 120 分钟、截止 2026-12-18 的任务，生成 2026-11-11～11-25 两周草案：`status=draft`，2 个时间块，无未排入、缺口或冲突。
- 结论：导入、双状态、缺密钥兜底与计划生成路径符合脚本；依赖模型的识别、带引用问答与核对界面未在本次走查中执行。
