# 课程路径验收样本（C001）

对应 Issue #183（父任务 #23 / E80）。用于培养方案解析、课程依赖建模与拓扑排序的验收。

## 来源说明

`real/` 下的 PDF 全部来自学校教务处官网公开发布的文件（培养方案按年级归档，预修要求与替代关系为全校公示表），不含个人信息，无需逐份登记来源。其中：

- `2023计算机科学与技术_专业.pdf`、`2026计算机科学与技术_专业.pdf`：同一专业两个年级版本，用于版本差异场景。
- `2025计算机科学与技术（辅修）.pdf`：辅修方案，体量小、结构完整，用于全量解析基准。
- `预修要求-计算机切片.pdf`：从全校《课程预修要求》公示表裁出的第 14、15 页（计算机相关条目，序号 165–240），用于强制先修关系解析。
- `替代关系-计算机切片.pdf`：从全校《课程替代关系》公示表裁出的 19 页（含 CS 课程代码的页，64 个替代组），用于替代方向（可相互替代 / 单向）与课程组建模场景。

培养方案正文不含先修信息；强制先修关系以预修要求公示表为准。真实数据中不存在并修与建议先学关系，这两类只有 `synthetic/` 下的合成样本。替代关系表原表 749 组在 PDF 中按替代方、被替代方两个视角各出现一次，切片只保留按替代方排序的视图，同组不重复收录。

## 目录结构

- `real/`：真实 PDF 样本。
- `expected/`：与真实样本对应的预期标注 YAML，由 `scripts/draft_course_path_expectations.py` 机器起草。
- `synthetic/`：合成反例与边界场景（成环、先修缺项、并修与建议先学），人工编写，可直接作为验收依据。

## 预期标注格式

每份 YAML 头部带 `_meta`：`source`（对应 real/ 下的文件）、`scenario`（验收场景）、`generated_by`、`needs_human_review`。

- 培养方案：`courses` 逐门列出代码、名称、必修/选修、学时、学分、开课单位、年级、学期与 `page`（PDF 页码，1 起）；`groups` 列出各组要求学分与门数；`rows_needing_review` 列出机器无法解析的行（如多学期开课、学期缺失的"空"行），这些行对应产品规则中的"待核对字段"，验收时不得补造。
- 预修关系：`relations` 逐条列出序号、课程代码/名称、开课单位、预修课程名/代码、预修课最近开课学期、预修课状态（范围内 / 已停开/更名），`slice_page` 为切片页码，`original_page` 为原公示表页码。已停开/更名条目对应依赖缺项场景，不得静默忽略。
- 替代关系：`substitutions` 逐组列出序号、组 ID、替代方与被替代方（各含 `names`/`codes`/`credits` 列表与原文行 `raw`）、`direction`（可相互替代 / 单向（左→右））、`is_course_group`（整组替代标记）。单向替代不得反向使用，课程组不得只换其中一门。

## 起草与复核流程

脚本使用 uv 的 PEP 723 内联依赖：Python 3.12、pypdf 6.19.0、PyYAML 6.0.3。首次运行需要下载依赖，不依赖全局 Python 环境，也不增加后端运行依赖。

1. 运行 `uv run scripts/draft_course_path_expectations.py` 重新生成 `expected/`（脚本只读 real/ 下已登记 PDF）。
2. 脚本会报告"疑似漏匹配"行数，这些行必须人工核对后在 YAML 中处理。
3. 运行 `uv run scripts/verify_course_path_expectations.py` 核对全部已声明字段与待核对原文；替代关系限定在同一组的连续原文块。运行 `uv run scripts/test_course_path_verification.py` 验证篡改字段与跨组误匹配会被拒绝。核对记录写入 [SPOTCHECK.md](SPOTCHECK.md)。
4. 所有 `needs_human_review: true` 的文件经人工对照原文抽查后，方可把标记置为 `false` 并作为验收依据；抽查比例与结果记录在 Issue #183。

当前状态：全部 expected/ 文件为机器起草稿，机器字段核对已通过 394/394（353 条课程与关系记录、41 条分组），另核对 6 条待核对原文。历史 Agent 视觉抽查与本次复验见 [SPOTCHECK.md](SPOTCHECK.md)。`needs_human_review` 保持为 true，待项目成员人工抽验确认后解除；本 PR 合并交付核对工具和样本补充，不代表 #183 人工验收完成。
