# Q001 中文检索与回答评测准备样本

登记编号 `CF-JSON-001`，版本 `q001-preparation-v1`。全部内容由项目人工构造，不包含真实学生资料、群聊或账户信息；使用范围为项目内部评测，登记见 [registry.csv](../../registry.csv)。

[cases.json](cases.json) 包含 11 个原文片段和 9 个问题。每个片段保存编号、工作空间／学期／课程／教学班、有效状态、合成定位及正文。每个问题保存适用范围、前三条检索结果的检查范围、相关片段、应回答的事实与逐字证据、不确定原因及回答类型。

| 问题编号 | 检查目标 |
| --- | --- |
| deadline-a / deadline-b | 同名课程不同教学班不能串用；另备旧学期、其他工作空间和已删除片段作干扰 |
| submission-paraphrase | 中文不同问法仍应找到提交方式；本轮只准备标注，未测真实检索 |
| missing-year-time | 不从学期猜年份，不补具体截止时刻 |
| conflicting-notices | 两份通知并列展示，缺替代声明不能擅自选新日期 |
| partial-coverage | 已读内容可回答，未导入／未识别部分明确提示 |
| conditional-rule | 保留培训条件、否定与例外限制 |
| no-material / archived-only | 没有有效资料时明确资料不足 |

`manual-transcript` 是人工编写的部分覆盖说明，**不是扫描件，也没有测试图片文字识别（OCR）**。定位也是合成定位，不对应真实附件。

预期事实与证据关系是项目预先编写的答案标注；目前未获得独立人工复核，不代表通用语义判分标准。脚本仅对完全匹配的预设事实和证据集合计分，其他表达进入待人工复核列表。不确定性按预标注原因编号比较，未验证任意自然语言解释是否充分。

## 第二批：干扰资料与全新题目

登记编号 `CF-JSON-002`，版本 `q001-preparation-v2`。[cases-v2.json](cases-v2.json) 包含 33 个原文片段和 15 个问题，**原样包含上面第一份样本的全部内容**：上面那 9 道题与 11 个片段一个字段都没有改，因此旧的三轮真实运行记录的样本指纹依然有效。

新增的两类材料：

- **同课程干扰片段（17 段）**：加在已有问题的同一课程、同一教学班范围内，措辞高度相似但不是答案。例如物理 A 班同时存在「实验报告一」「第二次习题」「期中考试」三份通知。原来每个范围内最多两段有效资料，检索几乎不会挑错；加完之后部分范围内有效资料多于前三条检索结果，才能看出向量模型排序的差别。
- **全新题目（6 道）及其独立课程范围（5 段资料）**：算法、英语、统计学、数据结构四门课的题库没有参与过提示词调试，用于检查不是「背答案」得来的效果。

| 新问题编号 | 检查目标 |
| --- | --- |
| algo-hw1 | 一句话里问两件事，要分别答 |
| eng-grading | 从成绩构成的多句话中挑对那一句 |
| stat-paper-words | 原文写「见后续通知」，应说不知道 |
| ds-exam | 两份通知日期不同，应指出冲突 |
| physics-a-2nd-deadline | 与第一次习题同范围，考能不能挑中 |
| os-lab2-deadline | 原文没写截止日期，应标缺失 |

美术（art）与音乐（music）两个范围**故意不加**任何干扰片段：那两道题考的就是「没有可用资料」。

运行第二批需要显式指定样本文件，例如：

```powershell
python scripts/evaluate_qa_live.py --execute --cases samples/synthetic/q001/cases-v2.json --budget-cny 3 --output-dir data/q001/live-batch2 --env-file backend/.env
```

不加 `--cases` 时仍读第一份 [cases.json](cases.json)，旧命令行为不变。

运行方式、记录格式、隐私边界和剩余工作见 [Q001 评测准备说明](../../../docs/verification/Q001-preparation.md)。
